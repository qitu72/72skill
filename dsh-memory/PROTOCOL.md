# 分层记忆协议（PROTOCOL）

> 本协议由用户与 agent 于 2026-09-06 共同定稿。所有在 D:\aolong 及其子工作区工作的 agent 必须遵守。
> 记忆根：`D:\aolong\.dsh-memory`（项目群内所有窗口共用一份）。
> 适用范围：任何打开 `D:\aolong` 或其子目录（如 `D:\aolong\72`、`D:\aolong\Products`）的 DSH 窗口。

## 一、为什么

同一窗口延续长线项目，上下文会涨到 100%。目标：上下文水位 <80%；触发收口后 ≤20%；任意历史细节可经 ≤2 次检索取回；续接质量不下降。

## 二、存储布局（固定路径，相对记忆根 D:\aolong\.dsh-memory）

- **常驻层**：`STATE.md`（≤3K token：目标 / 进度 / 下一步 / 决策约束 / 未完成 / 索引）
- **按需层**：`archive/YYYY-MM-DD-<主题>.md`（每份 ≤5K token，阶段详情）
- **底账层（免费，系统自带）**：各窗口的会话日志按窗口自己的工作区落盘——`~/.dsh/sessions/<工作区slug>/session-*.jsonl`（如 `--D-aolong--`、`--D-aolong-72--`、`--D-aolong-Products--`）+ Web「轨迹」标签页。压缩不删、永不重写。
- **灾备层**：`BOOTSTRAP.md`（自包含重建说明：机制/架构/绝对路径/模板/决策日志。换终端、换 Agent 或文件遗失时，把它整份发给任意 LLM 说「按此重建」即可；与 PROTOCOL 冲突时以 PROTOCOL 为准，除非 PROTOCOL 已丢失。异地快照：`cnb.cool/72boom/72skill` 仓库 `dsh-memory/` 目录，收工推送时覆盖更新）
- **体检脚本**：`verify.ps1`（一键核验：核心文件 / STATE 预算 / 索引引用 / contextWindow 配置 / tmpdir 三态清点）

## 三、行为规则

1. **每次会话开始**（含新窗口、/compact 之后）：先读 `D:\aolong\.dsh-memory\STATE.md`；需要细节再按索引读 archive 或 grep 对应工作区的会话日志。
2. **每个里程碑完成**（章节 / 大版本 / 重大决策 / 用户喊停）：写一份 archive + 增量更新 `STATE.md`（不重写历史）。
3. **上下文仪表 ~80%**（约 80 万 token）：执行收口——更新 `STATE.md` → 提醒用户发 `/compact` → 压缩后重读 `STATE.md` 对齐。
4. **检索预算**：任一事实 ≤2 次工具调用；读完的细节留在会话内，由压缩周期性回收。
5. **archive 超过 50 份**：把最旧一批合并蒸馏进 `STATE.md` 附录。
6. **tmpdir 残留治理**：判定在途 = 与当前 web 进程同 pid 且最后写入 <30 分钟 → **不动**。清扫前置 = 逐个核验对应正式文件存在（存在→冗余可清；不存在→全库同名搜索，寻回则清、寻不回留待用户判断）；一律回收站 + 静态绝对路径 + 执行前打印清单。
7. **STATE 尺寸纪律**：STATE.md 超过 ~6KB（约 3K token）就地收口压缩——细节移入 archive，STATE 只留日期 + 一句话 + 指向 archive 的索引；「下一步」只保留仍然有效的事项。
8. **体检**：收口后 / 重建后运行 `D:\aolong\.dsh-memory\verify.ps1`，全 PASS 才算收口完成。

## 四、收口检查清单（零遗漏）

- [ ] 目标与当前进度准确
- [ ] 下一步唯一且明确
- [ ] 关键决策与约束无遗漏（含用户偏好 / 禁忌）
- [ ] 未完成事项全列
- [ ] 索引指向有效文件

## 五、生命周期（长期治理）

- **进行中**：原地增量维护
- **已完成**：整个工作区挪到 `D:\aolong\_archive\<名>\`；会话日志先导出留档再删，或保留最近一个
- **临时 / 废弃**：删工作区 + 删 `~/.dsh/sessions/<slug>/`
- **72 知识库红线**：`D:\aolong\72` 是 Obsidian 知识库，不放无关内容；记忆文件一律在 `D:\aolong\.dsh-memory`（72 的 .gitignore 无需记忆排除，因为记忆不在那里）
