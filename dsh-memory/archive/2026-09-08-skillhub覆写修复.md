# 2026-09-08 — skill-hub 选技能覆写输入框修复（思思）

## 背景

兔兔反馈：对话框已输入文字后，点「🧩 技能」选中技能，输入框原文字消失。要求无论有无已输入内容，选技能都不得覆写。修复后兔兔实测通过（2026-09-08 晚）。

## 根因（两阶段叠加）

1. **API 面**：dsh 宿主 `conversation.input.left` 槽位的 `inputActions` facade 只有 `setDraft / addImages / removeImage / pruneImages / submit`（源：`@deepseek-ai/dsh-client-ui-conversation/lib/client.js` L11495-11509），**不存在** `insertText`/`append`——skill-hub 旧版调它们是静默 no-op（2026-08-24 曾因此改为 `setDraft`）。
2. **语义坑**：`setDraft(text)` 是**整体替换草稿**，不是插入。选技能后 `setDraft(技能指令)` → 已输入文字被整段吃掉。

## 修法（追加式回填）

- 槽位组件经 `props.useInput` hook（uiSession provide 通道声明 `hooks:["conversation","input"]`，hook 源转 `use<Name>` prop；session 作用域槽位均可用——同架构 `dsh-composer-attachments` 是成熟参照）读实时草稿 → 拼接 → `setDraft` 写回。
- 拼接规则：**指令句变体**（desktop 部署版 `pick()`）：`原文（去尾空白）+ \n\n + 指令块`，整段已存在则去重不重复追加；**@token 变体**（kit/web 版 `insert()`）：`原文 + 空格 + @技能名`，`endsWith` 去重。空草稿原样填入。
- 槽位注册处必须透传 `useInput: props.useInput`。

## 第四轮：灰底标识的正解——lexicon source（同日深夜续）

兔兔反馈桌面端「灰底圆角小标识」没出现，问是否要重启。复盘结论：**不是重启问题，是第三轮方案附着点不成立**（此前低分辨率截图验证误判，已认错）。机制真相：
- 核心 `scanTextRefs` 只对 **lexicon 精确成员**生成 TextRefNode（`lexicon.get('@')?.includes(name)`），技能名不在 at-file 的工作区文件索引里 → `[data-composer-text-ref]` 从未生成 → 灰底 CSS 无附着点。
- 另有核心正则限制：`TEXT_REF_RE=/@([\w-]+)/` **不吃点号**——`1password-1.0.1` 这类带点技能名永远匹配不上（无点号如 72-card/72-hasang 可匹配）。
**正解（已实施）**：skill-hub 通过 `inputTriggers.registerSource(source)` 注册自己的 lexicon source（trigger:"@", name:"skill-hub"，candidates/onPick/lexicon/subscribeLexicon 完整契约，对照 at-file 的 createAtFileSource）。效果：① 行内 `@技能名`（无点号）变成 TextRefNode → 灰底 pill 生效；② **@ 弹窗现在能搜技能**（WorkBuddy 同款体验）。源注册按变体取数：desktop live/kit-legacy 走 `host.call("skillHub.list")`，kit/package 走 `/api/skill-hub/list`（flatten groups→skills）。
**部署坑（已记 SPEC 级教训）**：① esbuild 沙箱 EPERM——JS shim 起原生二进制 spawn 失败（SPEC §8.3 同款），解法=直接调用 `@esbuild/win32-x64/esbuild.exe`；② `const out` 被 `out = out.concat()` 重赋值——严格模式下非法，**node --check（非严格）拦不住，esbuild 才是真门禁**（已改 push 循环）。
**3080 全流程实测**：置顶 ✓ 聚拢 ✓ `@72-card` 灰底 pill（DOM 抽到 `[data-composer-text-ref]`=" @72-card"）✓ 引用条隐藏 ✓ 按钮幽灵 ✓；带点技能名（1password-1.0.1）仍为纯文本=核心正则限制，如实告知兔兔。
