## 方案对比结论

| 方案 | 结论 |
|---|---|
| 内置压缩 | 有损（固定 8 段摘要 ≤8K），但自动、事务化、原地；保留为兜底 |
| 用户原案（写大文件+清空） | 「全量重写历史」成本不可行；「清空上下文」DSH 无原生操作；读回又占上下文 |
| 分层记忆 + 压缩兜底（选定） | 底账（会话日志免费无损 + 轨迹可视）→ 常驻 STATE.md（1-3K）→ 按需 archive + grep 检索 |

## 关键机制确认

- 压缩只遮蔽表层，原始事件全留在会话日志；轨迹视图按日志渲染，压缩前后全量可见
- 轨迹是浏览器 UI 投影，不进模型上下文；模型取回细节靠读磁盘日志（grep/read）
- DSH 会话的工作区在创建时定死（= 窗口打开时的目录），dsh-workspace 只负责侧边栏分组/排序/归档，无原地迁移会话功能
