## A. 症状与定位

- **现象**：DSH Desktop 2.0.5（compatibility 模式，win32）窗口右上角，侧边面板（dsh-better-sidebar「Files/侧边卡片」）的 PanelBottom/PanelRight 切换按钮**压在 Windows 原生最小化/最大化按钮上**，用户口述「侧边卡片按钮又重叠了」。
- **取证手段**（token 间接路线，均只读）：
  - Playwright 无头加载 3080/43120 真实 UI：cookie 由 `$DSH_HOME/.credentials.yaml` 的 `client-connection/browser-session` grant 密钥本地铸造（HMAC v1 格式，与 `dsh-client-connection` 的 BrowserAuth 校验完全一致；密钥不落盘不打印）。**桌面 harness home = `~/.dsh`（与 3080 web 同源），不是 `Roaming\dsh-desktop\harness`（那是旧手工安装残留）**。
  - Win32 `PrintWindow(PW_RENDERFULLCONTENT)` + Per-Monitor DPI 感知抓真实窗口像素，放大右上角实锤重叠。

## B. 根因链（代码级）

1. **桌面 2.0.5 的 compatibility 模式在 win32 上也是定制框**：`lib/electron-runtime-DLNj0vyk.js` `compatibilityWindowOptions()` → `customChromeWindowOptions({ titlebarHeight: 36 })` → 无边框 + `titleBarOverlay { height: 36 }`——原生 —/□/✕ 直接画在网页内容顶层右上 36px 带内；HTML 标题栏（`DesktopFrameTitlebar`，36px drag 带 + 左侧三个图标按钮 + 居中身份）负责拖拽区。
2. **桌面壳给 renderer URL 盖戳**：`src-DGihCtmE.js` `desktopRendererUrl()` → `dsh-desktop-mode=compatibility`、`dsh-desktop-platform=win32`、`dsh-desktop-titlebar-inset=36`（extended/compatibility 且非 linux 都盖）。
3. **dsh-better-sidebar 0.14.0 只认 advanced**：`src/client/desktop-env.ts` `parseDesktopEnv()` 仅在 `mode==='advanced' && platform==='win32'` 返回 `win32OverlayTop=32`，其文档还写着「compatibility mode keeps the native frame——无需适配」（旧版桌面行为，2.0.5 已变）。
4. **于是**：插件的 toggle cluster（`position:absolute; top:3px; right:10px`，宿主 `[data-dsh-panel-host]` 为 `position:fixed; inset:0` 的 viewport 层）正好落进原生标题栏按钮区 → 重叠。
5. 插件**已有完整的让位机制**（`data-dsh-title-bar-compat` body 属性 + `--dsh-title-bar-strip` 变量：cluster 下移、面板内容 padding-top），只是自动触发条件漏了 2.0.5 的 compatibility/extended。手动 pref（设置里的 titleBarCompat）本可绕过，但兔兔不应被迫手动补偿平台回归。

## C. 修复（最小补丁，用壳自己的戳）

- `win32OverlayTop` 改为：win32 上 `advanced→32`（原行为不变），其余模式→戳值（compatibility=36），无戳→0（纯浏览器/社区壳不受影响）；darwin 不受影响（红绿灯在左上）。
