## 七、skills-sync v2（同日下午，兔兔要求全盘排查）

### 审计发现（v1 五问题）
1. **CONFLICT 检测永不触发（设计缺陷）**：v1 在同步后检测哈希，但 /XO 新者胜覆盖早已发生——文档承诺「双端编辑→停下问兔兔」实际是静默覆盖丢失；唯一触发路径是 mtime 相同内容不同（robocopy 乒乓），概率极低。
2. **C(N,2) 两两同步不 scale**：3 端 6 趟、5 端 20 趟 robocopy。
3. **硬编码三腿**：新 Agent 必须改源码；totalCopied 统计漏计 A→B 趟（小 bug）。
4. **junction 相关注释过时**：实测 CodeBuddy junction 已清零（/XJ 保留无害）。
5. **游离库**：`.agents\skills`（29 技能，三主库子集）与 `.qoderwork\skills`（17 技能，全是主库没有的宝玉系技能如 baoyu-*、docx、deep-research）完全不在同步网内。

### v2 改造（`scripts/sync_skills.ps1` + 新增 `sync_skills.json`）
- **任意多端 hub-and-spoke**：canonical（默认 workbuddy）↔ 每腿双向；配置文件加一行即接新 Agent（`~` 展开、相对路径按脚本目录解析）；无配置文件=旧三腿行为（向后兼容）。
- **同步前哈希快照**：差异技能先列清单；mtime 相同（±2s）内容不同 → HARD CONFLICT 停手 exit 2（修死检测）。
- **OVERWRITTEN 透明报告**：同步后列出哪端被哪端覆盖（mtime 新者胜不再静默）。
- **autoDiscover 仅提示不自动纳入**（防止把 109 技能灌进新客户端自己的库）；统计修正；`per-end skills` 验收。
- **测试**：%TEMP% 假库 16 场景全过（传播/覆盖报告/硬冲突 exit 2/3 腿/独有保留/一致判定）；测试驱动踩坑：Write-Host 走 information stream 需 `*>&1` 捕获、$PSScriptRoot 配置查找必须复制脚本进测试目录。
- **部署**：v1 备份 `.bak3-v1`；SKILL.md v2 已写 canonical 并同步三端（哈希 EF4DC053 一致）；真同步输出验证 PRE-SYNC + OVERWRITTEN 精确指向本次改动。
